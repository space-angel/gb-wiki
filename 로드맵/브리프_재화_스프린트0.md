## 왜 "새로 쓰는 게 없다"고 하는가

08-17에 Slack `#3_스토리`에 공유하신 "01. 결정 사항 로그 / 설정 현황" 문서, 이미 완성도가 매우
높습니다(19개 섹션, ✅/👀/❓/⚠️/🗑️ 상태 표기까지 체계적으로 정리됨). 스프린트 0에서 할 일은
**이걸 Notion sandbox에 정식으로 옮기고, 팀이 실제로 참조할 수 있게 만드는 것**이지, 내용을 새로
만드는 게 아닙니다.

## 1. `01. 결정 사항 로그 / 설정 현황` — Notion sandbox 등록

**할 일**: Slack에 쓰신 그대로 Notion(Z-B 이재화 sandbox)에 페이지로 등록. 형식(✅확정/👀확인
필요/❓미정/⚠️충돌확인/🗑️폐기)은 이미 저희 위키의 상태 표기 체계(`확정/잠정/검토필요`)와 사실상
1:1 대응이라 그대로 써도 됩니다.

**등록하시면서 같이 확인할 것 — 이미 저희 쪽에서 발견한 충돌 1건**:

`ADR-15`로 이미 반영해뒀습니다: §6 "보조 유품 총 6개(메인당 2개×3축)"가 기존 `ADR-3`(10~12개)과
충돌해서, **사용자(spaceAngel) 판단으로 6개를 확정으로 채택**하고 `ADR-3`를 개정하는 `ADR-15`를
새로 만들었습니다. Linear `GBG-187`(D3)에도 반영됨.

**다만 이건 재화 본인이 직접 확인 사살한 게 아닙니다** — 제가 Slack 문서 텍스트만 보고 대신
판단한 거라, **다음 `#0_결정논의_큐`에서 "네, 6개 맞아요"라고 한 번 확인해주시면** 완전히 마무리됩니다.
(`ADR-15` Open Question 2번 참조)

## 2. `02. 게임 구조와 연결되는 스토리 흐름` — 진행 중, 마저 작성

Slack에서 이미 목차를 잡아두신 대로:
- 게임 전체 기본 플레이 흐름
- 현실 ↔ 사령세계 관계
- 기록관의 사건 개입 방식
- 조사 → 사령세계 → 재탐문 → 재해석 구조
- 이해도와 스토리 진행의 관계
- 성불/제령/소멸이 스토리에서 갈라지는 지점
- 챕터 공통 구조와 챕터별 고유 구조 구분

**참고하시면 좋을 기존 자료**: `게임가이드/5_예제/04-07_플레이-흐름.md`,
`게임가이드/5_예제/04-08_감정-곡선.md`에 챕터1 기준으로 이미 정리된 내용이 있어서, 02번 문서를
"챕터1 한정"에서 "게임 전체 공통 구조"로 일반화하실 때 대조하시면 중복 작업을 줄일 수 있습니다.
