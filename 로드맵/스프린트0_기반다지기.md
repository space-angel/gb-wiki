# 스프린트 0 — 기반 다지기

> **한 줄**: 새 일을 시작하는 스프린트가 아니라, **지금 이미 진행 중인 것들을 스프린트1이 시작될 수
> 있는 상태로 마무리**하는 스프린트다. 개발·아트·스토리는 원래 하던 걸 계속하면 되고, **지호(기획)의
> 갈림 해소만 이번에 새로 명시적인 작업으로 잡는다.**

## 왜 스프린트 0가 필요한가

스프린트 1(현실세계를 걷는다)을 설계하면서 "지금 하던 작업 끝나면 시작"이라고만 뭉뚱그렸는데, 그럼
① 언제 끝나는지 기준이 없고 ② 결정 담당자(지호)가 로드맵에서 아예 빠져 있었다. 이 문서가 그 두 개를
메운다.

## 트랙 4개

### 1. 호윤 (개발) — E0 인프라 마무리

| 이슈 | 상태 |
|---|---|
| `E0-S3` 게임 상태 저장·복원 | 작업중 |
| `E0-S3-T1` 저장 데이터 모델 + Newtonsoft + ISaveable | 작업중 |
| `E0-S3-T2` SaveSystem 서비스 | 할 일 |
| `E0-S3-T3` 저장 시스템 통합 + 더미 검증 | 작업중 |
| `E0-S4` 시스템 간 이벤트 전달 | 백로그 |
| `E0-S5` 이해도 4플래그 관리 | 백로그 |
| `E0-S6` 디버그로 상태 강제 | 백로그 |

**완료 기준**: 세이브·이벤트·이해도플래그·디버그 4개 시스템이 다 "완료" 상태로 옮겨지면 끝.
스프린트1의 개발 작업(E1-A-T1/T2)이 이 위에서 동작하므로, 최소한 `E0-S3`·`E0-S4`까지는 끝나야
스프린트1을 시작할 수 있다. `E0-S5`·`E0-S6`은 병행 가능(급하지 않음).

### 2. 재화 (스토리) — 결정 로그·스토리 흐름 확정

| 문서 | 상태 |
|---|---|
| 01. 결정 사항 로그 / 설정 현황 | 초안 공유됨(Slack, 2026-08-17) — Notion sandbox로 정식 등록 필요 |
| 02. 게임 구조와 연결되는 스토리 흐름 | 진행 중 |

**완료 기준**: 두 문서가 재화 sandbox에 정리돼 있고, §17("현재 팀 확인 필요 사항")에 나열된 항목 중
스프린트1에 필요 없는 건 미뤄도 되지만 **아래 "지호 트랙"과 겹치는 항목은 지호와 함께 정리**한다.

**⚠️ 지호 트랙 D11(NPC A/V 배정)이 재화의 01번 문서 §15("추가 정리 필요")에 막혀 있다** — 이유미·
어머니 상세 진술 구조, NPC별 해금 조건이 없으면 지호가 A/V를 배정할 근거 자체가 없음. D6·D9도
방향성 정도는 재화 확인이 필요. 상세: `로드맵/브리프_재화_스프린트0.md` §3,
`로드맵/브리프_지호_스프린트0.md`의 D6·D9·D11 항목.

**완료 기준**: 스프린트1의 `E1-A-T3`(도면)·`E1-A-T4`(타일)를 바로 시작할 수 있는 상태. 이 트랙
자체가 스프린트1 작업의 준비 단계라 별도 Linear 이슈는 없다.

### 4. 지호 (게임디자인·기획) — 갈림 해소 ← 이번에 새로 명시

지호 담당으로 Linear에 이미 **결정 대기 이슈 9건(`E0-D1`~`D9`)**이 쌓여 있었다. 이번에 우리가
찾은 `게임가이드/6_현황/06-03` 갈림 4건과 대조해보니 상당수가 같은 사안이었다.

| Linear 이슈 | 내용 | 대응하는 갈림/미결 | 우선순위 |
|---|---|---|---|
| `GBG-174` E0-D2 | 챕터1 진행 게이트 순서를 확정한다 | **C-1 사령세계 획득구조** (순차 vs 동시 노출) | 🚨 최우선 — 스프린트1 이후 모든 설계를 막고 있음 |
| `GBG-154` E0-D1 | 핵심 유품 3종을 확정한다 | **C-2 메인유품 명칭** (4개 버전 중 어느 것) | 높음 — 재화 결정로그가 이미 "졸업사진/핸드폰/취준파일" 확정이라 지호 쪽 카운터사인만 남음 |
| `GBG-159` E0-D7 | ADR 번호 체계를 통합한다 | Notion ADR DB 신규/구버전 중복 (`raw/00_컴플라이언스/노션_위치_지도.md` §3) | 중간 |
| `GBG-158` E0-D6 | 판매 임계 수식을 확정한다 | 보조유품 판매 시점 (재화 결정로그 §6 ❓미정) | 중간 |
| `GBG-171` E0-D8 | 졸업사진 인계 규칙을 확정한다 | C-2와 연동 | 낮음 |
| `GBG-172` E0-D9 | 소멸 부적 아이템을 정의한다 | 성불/제령/소멸 §9 ❓미정 | 낮음 |
| `GBG-173` E0-D1 | 이해도 판정 규칙을 확정하고 문서화한다 | ADR-12 (Proposed) | 진행 중 (지호가 이미 작업중으로 옮겨둠) |
| `GBG-160` E0-D3 | 이해도 판정 규칙을 확정한다 | `GBG-173`과 **같은 주제, 다른 이슈** — 중복 | ⚠️ 정리 필요 |
| `GBG-155` E0-D2 | 사령 단서 ①②③을 확정한다 | `GBG-174`와 **번호 중복**(둘 다 D2) | ⚠️ 정리 필요 |
| `GBG-156` E0-D4 | 카드 대화 규격을 명세한다 | NPC 대화 시스템(스프린트3용) | 낮음, 급하지 않음 |
| `GBG-157` E0-D5 | 위상 추상화 룰을 확정한다 | 불명확 — 지호 본인 확인 필요 | ? |

**정리가 필요한 것**: `D1`과 `D2` 번호가 각각 두 이슈에 중복 배정돼 있다(`154`↔`173`, `155`↔`174`).
번호 체계 통합 작업(`GBG-159`, E0-D7) 자체가 이걸 고치는 일이므로, **`GBG-159`를 제일 먼저 처리하면
나머지 번호 혼란도 같이 풀린다.**

**아직 Linear 이슈가 없는 갈림**: C-3(NPC A/V 배정), C-4(축-플래그 매핑)는 위 9건 어디에도 안
걸린다. 번호 정리(`GBG-159`) 직후에 `E0-D10`, `E0-D11`로 지호가 새로 만드는 걸 권장.

**완료 기준**: `GBG-174`(C-1) 확정이 최소 조건. 나머지는 스프린트1 진행 중에도 병행 가능.
