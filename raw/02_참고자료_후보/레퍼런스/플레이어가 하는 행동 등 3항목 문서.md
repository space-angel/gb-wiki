```

      ▼

(기록만 한다)
      │
      ▼

      ▼

(연출만 실행한다)
```

이렇게 역할을 명확하게 분리하면, **단서를 어떤 순서로 수집하든 진행은 안정적으로 유지**되고, **스토리 연출도 조건에 맞춰 일관되게 제어**할 수 있다. 이게 바로 **《Return of the Obra Dinn》이 사용하는 "탐색은 자유롭게, 진행은 조건부로"**라는 구조의 핵심 원리다.

### RETURN OF THE OBRA DINN 작동방식

> **Obra Dinn은 "단서를 N개 모으면 진행" 같은 시스템이 아니다.**
> **'탐색'과 '확정'을 완전히 분리한 게임이다.**

즉 내가 전에 예시로 든 "4개 모으면 O=True"는 **너희 게임을 설명하기 위한 예시**였지, Obra Dinn의 구현 방식은 아니다.

## 개발 관점에서 보면

Obra Dinn의 핵심은 **"플래그 게임"이 아니라 "데이터베이스 게임"**에 가깝다.

예를 들면 내부 데이터는 이런 식일 가능성이 높다.
```
Scene
- Open / Close

Crew
- Identity (플레이어 입력)
- Cause (플레이어 입력)
- Killer (플레이어 입력)
- Confirmed (bool)

Validation
- Confirmed가 false인 Crew만 검사
- 정답이 3명 이상이면 Confirm 처리
```

즉 **"단서를 먹으면 이벤트가 열린다"**가 아니라,
- 탐색 시스템은 **정보(Scene)를 개방**하고,
- 플레이어는 그 정보를 이용해 **가설을 입력**하며,
- 검증 시스템이 일정 규칙(3명 동시 정답)에 따라 **가설을 확정**하는 구조다.

그래서 Obra Dinn은 탐색과 추리를 완전히 독립시켜 놓았고, 이 점이 지금 너희가 만들고 있는 "탐색은 자유롭지만, 진실은 조건을 만족해야만 확정된다"는 구조를 설계할 때 가장 참고할 만한 부분이야.

# 추리보드 시스템과 연관

## 추리 보드 2단계 설계에 Obra Dinn 구조 매핑

### 기본 전제 정리

유품정리사의 이해도 시스템은 O/A/V/R 4개 flag가 **순차적**으로 도달되는 구조죠. Obra Dinn의 "3명 세트 확정" 방식을 그대로 가져오기보다, 두 게임의 근본적 차이를 먼저 짚을게요.

- Obra Dinn: 60명이라는 **병렬적 다수 대상**을 교차검증
- 유품정리사: 김태현 1인에 대한 **단일 인물의 이해도 심화**

그래서 "여러 사람을 동시에 맞추는" 구조보다는, **"하나의 진실에 도달하는 여러 단서 조합"** 쪽으로 응용하는 게 맞을 것 같아요.

### 2단계 보드 설계안

#### 1단계 보드(기존)와의 역할 분담

1단계가 O_reached, A_reached 정도의 **표면적 사실 확인**(김태현이 누구였는지, 어떤 사건이 있었는지)이라면, 2단계는 V_reached, R_reached로 가는 **해석의 영역** — 즉 "왜 그랬는가", "누구의 잘못인가" 같은 판단이 개입되는 구간이겠죠.

#### Obra Dinn식 교차검증 도입 지점

**① 단서의 "확정" 방식 — 즉시 피드백 금지**

1단계 보드에서 단서를 놓으면 바로 O/A flag가 반응하는 대신, **2개 이상의 단서가 동시에 배치되어야만** 보드가 반응하는 방식을 제안. 예:
- 단서 A(유류품) + 단서 B(NPC 증언)가 동시에 특정 위치에 배치될 때만 "딸깍" 확정
- 하나만 배치했을 땐 보드가 침묵 → 플레이어가 스스로 "이게 맞나?" 의심하게 만듦

**② 소거법 가속 구조 — R_reached의 단계적 개방**

말씀하신 "NPC 지정 규칙" 문제와 연결되는데, Obra Dinn처럼 **먼저 확정된 정보가 다음 추론의 전제**가 되는 체인 구조를 2단계 보드에 넣는 걸 제안:
- V_reached가 확정되기 전엔 R_reached 관련 NPC 후보군이 흐릿하게(이름 대신 실루엣/직책만) 표시
- V 확정 순간 후보군이 좁혀지며 R 관련 단서가 활성화

**③ 비선형 단서 배치 + 사후 재구성**

2단계 보드는 단서를 시간순이 아니라 **뒤섞어서 제시**하고, 플레이어가 인과관계를 스스로 재배열하게 하는 것도 고려해볼 만해요. 다만 이건 개발 리소스가 꽤 들어가니, 최소 버전으로는 "단서 카드에 타임스탬프를 안 보여주기" 정도로 시작할 수도 있습니다.

### 실무적 우선순위 제안

banjax님(전투/개발), 정인님(아트/UI) 리소스 감안하면:
1. **①번(동시 배치 확정)**이 가장 구현 비용 대비 효과가 큼 — UI 로직만 추가하면 되고 새 에셋 불필요
2. **②번(단계적 개방)**은 정인님 UI 작업 필요 (실루엣 → 실사 전환)
3. **③번(비선형)**은 챕터 2 이후로 미루는 게 안전
