# 이해도 시스템 구현 관점 피드백

## 1 )) 세분화 포인트 부터

"**세분화할수록 안정적**"이라는 피드백은 맞는데 무엇을 측정할지에 대한 이야기이고 (관찰/연결/검증/재해석 4종으로 나눈 거 → 이건 좋은 설계, 유지). 내가 짚은 건 "각 항목을 어떻게 저장할지"라서 결이 다름

세분화는 도메인을 4개 축으로 쪼개는 거에 대한 이야기고, 내가 짚은 건 저장 타입 차원(각 축을 연속 float로 들지 vs bool/enum으로 들지)이라 레이어가 다름

- 연속값이 위험한 이유는 동작 멱등성이 깨져서인데
- Omax가 콘텐츠 총량에 의존 → 유품/대사 하나 추가하면 분모 변함 → 세이브에 저장된 ON 값의 의미가 달라짐(0.79→0.74) 즉 "같은 입력→같은 상태"가 안 됨
- 단서 중복 획득/연결 롤백/재탐문 재수행 같은 케이스에서 +=1이 멱등적이지 않으면 점수가 이중 적립
- >> 임계 플래그("핵심 단서 N개 연결 달성 = true")로 가면 둘 다 사라짐 → 세트니까 멱등성 공짜, 콘텐츠 추가에 불변. 세분화 줄이자는 게 아니라 각 축의 타입을 이산화하자는 거

쉽게 비유하면 - 시험 과목을 국어/영어/수학/과학으로 나누는 건(세분화) 좋음. 근데 각 과목을 "전체 문제 중 몇 %"로 매기면(연속 %) 문제 수 늘 때마다 점수가 흔들림. 그래서 4종으로 나눈 건 그대로 두고, 각 수치 표현만 % → 통과여부로 바꾸자는 거임. 세분화 줄이자는 거가 아니다.

## 2 )) 엔딩 분기엔 결국 합산이 필요하지 않나 -> 이부분

여기 숨은 전제가 하나 있음: `여러 수치를 고려한다 = 하나로 합산한다` 근데 이 둘은 사실 다른 이야기임

**합산방식**: 4개를 가중치로 섞어 U=62.75% 하나로 만들어서 엔딩 판정 → 문제는 섞는 순간 어떤 항목이 부족해서 이 엔딩이 나왔는지 추적이 안 됨. 재해석 0인데 관찰,연결 만점이면 U가 높게 나와서 엉뚱한 엔딩 열릴 수도 있음

**조건 조합 방식**: 합산 안 하고 4개를 각각 보되 "어떤 조합이냐"로 엔딩이 갈림

> ☝🏻
> *성불 = 재해석 통과 AND 보스 특수페이즈 AND 최종대화 완료*
> *제령 = 검증 통과 AND 보스 격파 AND 최종대화 미달*
> *소멸 = 재해석 실패 AND 보스 존재 모름*
> **→ 다른 수치 모두 고려가 합산 없이도 이미 달성됨**

## 3 )) 4개 % → 통합 % → 트리거 → 보스 패턴 변화

파이프라인 구조는 좋음. but 이벤트 트리거→보스 패턴 변화로 엔딩 표현은 그대로 가져가도 좋을거 같은데 중간의 통합 % 만 위에 합산 문제 때문에 조건 조합 형식으로 바꾸는게 좋을거 같음

```
[기존 파이프라인] 4개 % → 통합 % → 트리거 → 보스 패턴 변화

[수정 파이프라인] 4개 통과여부 → 조건 조합 → 트리거 → 보스 패턴 변화
```
