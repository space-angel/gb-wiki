# 이해도 내부 표현 — 4종 이산 플래그 파이프라인

## 1. Context
ADR-001에서 이해도의 정의와 출력은 잠금됐지만, 내부적으로 이해도를 어떤 자료형으로 표현할지 미정이었다. 두 가지 모델이 경합했다.

**가중 합산 스칼라 모델**은 행위별 가중치를 부여해 단일 수치로 합산한다. 예: `U = 0.1·O + 0.2·A + 0.3·V + 0.4·R`. 익숙한 구조이고 임계값 분기가 쉽다.

**4종 이산 플래그 모델**은 관찰(O)·연결(A)·검증(V)·재해석(R)을 각각 boolean으로 표현하고 순서 의존적으로 진행한다.

두 모델 중 어느 쪽도 잠기지 않은 상태에서 지호의 메카닉 문서가 가중 합산을 잠정 가정해 작성되고 있었다. 이 채로 두면 입력 행위 가중치 수치를 결정해야 하고, 임계값 컷오프 수치를 결정해야 하고, 이게 다 Phase 0 작업량을 불린다.

또한 가중 합산 모델은 ADR-001의 원칙을 깰 위험이 있다. R 점수가 0이어도 다른 축 합으로 성불 임계값에 도달할 수 있다. 즉 "재해석 없이 성불"이 이론상 가능해진다.

## 2. Decision
이해도 내부 표현을 **4종 이산 플래그의 순서 의존적 파이프라인**으로 한다.

```
O_reached → A_reached → V_reached → R_reached
 (관찰)       (연결)       (검증)      (재해석)
```

각 플래그는 boolean 값이며, **이전 플래그가 true여야 다음 플래그 달성이 가능**하다.

### 2.1. 4종 플래그 정의
| 플래그 | 이름 | 달성 조건 | 현실세계 행동 |
|---|---|---|---|
| O_reached | 관찰 | `추후 문서에서 정의` | 탐색, 아이템 획득 |
| A_reached | 연결 | `추후 문서에서 정의` | 보드 연결, 가설 선택 |
| V_reached | 검증 | `추후 문서에서 정의` | NPC 대화, 교차검증 |
| R_reached | 재해석 | `추후 문서에서 정의` | 핵심 아이템 보드 연결 |

### 2.2. 엔딩 분기 매핑
| 엔딩 | 플래그 조건 |
|---|---|
| 성불 | O+A+V+R 전부 true |
| 제령 | O+A+V true, R false |
| 소멸 | O+A false 또는 보조 아이템 판매로 A 미달 |

엔딩 분기의 상세 트리거는 ADR-005에서 정의한다.

### 2.3. 보스 도전 가능 시점
보스 도전은 이해도 플래그와 무관하게 **O_reached 시점부터 항상 가능**하다. 메트로배니아 구조 원칙(첫 진입부터 보스 도전 가능)을 유지한다. 이해도는 종결 방식을 바꿀 뿐, 도전 자체를 막지는 않는다.

## 3. Status
Accepted. 2026-06-15 회의에서 4명 합의. 노션 ADR-002 문서로 잠금됨

## 4. Consequences

#### 4.1. 긍정적 결과
R 플래그 없이는 성불이 불가능하다. 이게 가중 합산 모델 대비 가장 큰 이득이다. ADR-001 "재해석이 종결의 핵심"이라는 원칙이 데이터 구조 자체로 강제할 수 있는 것이다.

가중치 수치 설계가 불필요해진다. 임계값 컷오프 수치 결정도 불필요해진다. 4개 boolean의 AND 조합만 평가하면 된다. Phase 0 작업량이 줄어든다.

구현이 단순하다. 4개 bool 체크가 전부다. ScriptableObject·세이브 파일·이벤트 시스템 모두 단순해진다.

파이프라인 구조가 게임 플로우와 1:1 대응한다. 탐색(O) → 추리(A) → 검증(V) → 재해석(R) 흐름이 자연스러운 게임 진행과 일치한다.

#### 4.2. 부정적 결과 / 제약
플레이어 진행 표현이 이산적이다. "지금 60%쯤 왔다" 같은 중간 표현이 불가능하다. 단 ADR-001이 어차피 수치 비노출을 명시하므로 실질 손실은 없다.

플래그 간 가중치를 통한 미세 조정이 불가능하다. 디자인 변경이 필요할 경우 새 플래그를 추가하거나 트리거 조건을 수정해야 한다.

종합 이해도 U(챕터 합산)의 산출 공식이 더 복잡해진다. 4종 boolean을 어떻게 챕터별로 합산해 최종 엔딩에 반영할지 별도 설계가 필요하다. ADR-013 또는 후속 결정에서 다룬다.

#### 4.3. 대안 검토 (기각)
| 대안 | 기각 사유 |
|---|---|
| 가중 합산 스칼라 (`U = 0.1·O + 0.2·A + 0.3·V + 0.4·R`) | R=0이어도 성불 임계값 도달 가능. ADR-001 원칙 위반 |
| 단일 수치 (0~100) | 측정 의미 약함. 수치 변화 사유를 작가가 일일이 설계해야 함 |
| 5단계 이상 플래그 | 게임 플로우와 1:1 대응 깨짐. 작가·구현 부담 증가 |

## 5. Compliance
본 ADR을 따르는 모든 후속 설계는 다음을 준수한다.
- 이해도를 단일 수치로 표현하는 새 메카닉을 도입하지 않는다.
- 4종 플래그의 순서 의존성을 깨는 트리거를 만들지 않는다. (예: O 없이 A 달성)
- 보스 도전 가능 시점을 이해도 플래그에 종속시키지 않는다.
