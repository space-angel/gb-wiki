## 2. 재화 — 우선순위

Slack에 이미 써둔 내용이 대부분이라 새로 쓸 건 거의 없음. 다만 아래 3개 섹션이 지호 작업을 막고 있어서 **그 부분만 먼저** 채워야 한다.

| 2 | 「01. 결정 사항 로그」 Notion sandbox 정식 등록 | 등록하면서 `ADR-15`(보조유품 6개) 본인 확인 필요 |

## 3. 크로스 디펜던시

```
재화 §15 (NPC 진술 구조 미정리)  →  지호 D11 (NPC A/V 배정, GBG-176)
```

Linear에 `blocked-by` 관계로 걸어둠. 재화가 §15를 채우기 전엔 지호가 손댈 수 없는 유일한 항목 — **이번 주 안에 초안 나올 수 있는지 확인 필요.**

## 4. NPC 진술 구조 정규화 — 표로 정리하는 방법

재화가 정리한 §15(NPC 현황)가 지금 자유 서술형이라 지호가 그대로 배정 작업에 쓰기 어렵다. 실제 게임 개발에서 진술/증언 구조는 보통 표(엑셀·시트) 형태로 정규화한다 — 굳이 엑셀일 필요는 없고, Notion 데이터베이스나 마크다운 표로도 충분하다. 핵심은 **컬럼을 고정해서 NPC마다 같은 항목이 채워지게 만드는 것.**

### 제안 컬럼 구조

| 컬럼 | 의미 | 비워두면 안 되는 이유 |
|---|---|---|
| NPC | 인물명 | — |
| 단계(A/V) | 이 NPC가 A(핵심 진술)인지 V(검증 진술)인지, 혹은 둘 다인지 | ADR-6이 "A·V 각 최소 2명"을 요구 — 이 컬럼이 비면 C-3 갈림이 절대 안 풀림 |
| 최초 인식 | 플레이어가 처음 만났을 때 하는 말 (판단을 유도하는 오판) | 04-07의 "최초 인식 → 1차 진술 변화" 흐름과 직결 |
| 해금 조건 | 이 진술로 넘어가려면 뭘 먼저 해야 하는지 (특정 유품 발견? 다른 NPC 방문?) | 지호가 D11에서 이걸 그대로 씀 — 없으면 배정 불가 |
| 1차 진술 변화 | 해금 후 바뀌는 말 | — |
| 2차 진술 변화 (있다면) | — | 모든 NPC가 2차까지 있을 필요는 없음 |
| 연결 조사축 | 이 진술이 어느 메인 유품 축(졸업사진/핸드폰/취준파일)과 엮이는지 | 04-05 조사축 구조와 대조 가능해야 함 |
| 모순/단서 | 이 진술이 드러내는 모순이나 단서 | 스토리 논리 검증용 |
| 출처 | 원문 근거 (Slack 링크, 결정로그 §번호 등) | 나중에 재검토할 때 원문 추적 가능해야 함 |

### 마크다운 표 예시 (Notion sandbox에 그대로 옮겨 쓸 수 있는 형태)

```
| NPC | 단계 | 최초 인식 | 해금 조건 | 1차 진술 변화 | 연결 조사축 | 모순/단서 | 출처 |
|---|---|---|---|---|---|---|---|
| 집주인 | O | "방에만 있던 백수" | (첫 만남, 조건 없음) | ... | ... | ... | ... |
| 이유미 | A | ... | ... | ... | 취준파일 축 | ... | ... |
| 상담사 | V | ... | ... | ... | ... | ... | ... |
| 어머니 | ?(Transition) | ... | ... | ... | ... | ... | ... |
```

**어머니를 어느 컬럼에 넣을지가 사실 C-3 갈림의 본질이다** — "단계" 컬럼에 A/V 둘 중 하나를 강제로 넣을지, 아니면 "Transition"이라는 새 값을 컬럼에 허용할지부터 표를 채우면서 결정하게 된다. 즉 이 표를 채우는 작업 자체가 §15 정리이자 C-3 갈림 해소 작업이 된다.

**적용 방법 제안**: 엑셀 대신 Notion sandbox 안에 데이터베이스(표)로 만들면, 나중에 지호가 "A만 필터" 같은 뷰로 걸러볼 수 있어서 더 낫다. 다만 지금 급한 건 형식이 아니라 **어머니 진술 구조를 이 컬럼들에 맞춰 한 번 채워보는 것.**

## 5. 정인 — 진행 상황 확인

이미 상당 부분 진행됨: 사이드뷰로 작업 중, 중문 안팎 대비 도면 이미 공유 완료, 픽셀 밀도도 직접 잡는 중. 오늘 물어볼 건 딱 하나.

### 질문

> **원룸 다음에는 어떤 공간(모듈)을 어떤 순서로 작업할 지**

도면에서 벽 레이어만 받아 Unity에서 컨트롤러·그레이박스 타일을 만들어서 공유정, Linear에도 등록해뒀다(아래 §6). 남은 건 원룸 다음 공간의 작업 순서뿐이라 오늘은 그것만 확인

## 6. 산출물 흐름 — Linear 등록 완료

```
정인 (GBG-198, 도면 확정 + 벽 레이어 추출)
   → 호윤 (GBG-196, 벽 레이어로 컨트롤러 충돌 + 그레이박스 타일)
   → 정인 (GBG-199, 최종 적용본 타일로 그레이박스 대체)
```

- `GBG-198` 상태를 **작업중**으로 갱신, 산출물을 "벽 레이어만 별도 추출해 전달"로 명시
- `GBG-196`에 "정인이 전달한 벽 레이어를 입력으로 사용" 명시
- `GBG-196` ← `GBG-198` **blocked-by** 관계 등록 (컨트롤러가 벽 레이어 없이는 시작 불가함을 Linear에도 반영)
