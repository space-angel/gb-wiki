# PART 1. 레퍼런스를 어떻게 잡을 것인가

## 1-1. 레퍼런스를 잘못 잡으면 벌어지는 일

### 실제 사례: 터틀크림 (RP7)
언리얼 서밋에서 공유된 사례. 아트디렉션 방향이 잡힌 뒤, 디렉터가 원래 쓰던 파이프라인(ZBrush)으로 작업했는데 **에셋 하나에 열흘이 걸렸다.** 그래서 파이프라인을 다시 잡았다. 디테일에 집착하게 되는 툴 자체를 최소화하고, 섬세하진 않지만 자기들이 정한 아트디렉션에는 충분한 퀄리티가 나오는 방식으로 갈아탔다.

3D 사례지만 교훈은 똑같다:
> **스타일을 먼저 정하고 작업 속도를 맞추는 게 아니라, 작업 속도에 맞는 스타일을 정한다.**

### 실제 사례: 원더포션 (산나비)
산나비 팀이 도트를 선택한 이유 중 하나가 명시적으로 "작은 규모의 팀에서 생산성을 확보할 수 있어서"였다. 취향이 첫 번째 이유였지만, 생산성이 바로 두 번째 이유로 붙는다.

그리고 산나비는 실제로 작업량을 줄이는 선택을 계속했다:
- 주인공 스프라이트를 **좌우 따로 만들지 않고 좌우반전으로 처리** (작업량 절반)
- 그 결과 사슬팔이 좌우에 따라 위치가 바뀌는 불일치가 생겼지만, **그 트레이드오프를 감수했다**
- 도트는 팀이 직접 찍고, **일러스트는 전부 외주**로 분리

주목할 점: 그들도 완벽하지 않았다. 좌우반전 때문에 설정 오류가 생겼고, 외주와 정보 공유가 안 돼서 엔딩 일러스트에서 팔이 반대로 나왔다. **그런데 게임은 대박 났다.** 완벽함이 아니라 완성이 목표다.

또 하나. 유승현 대표는 인터뷰에서 이렇게 말했다:
> 복잡한 것보다 단순한 것이 전달력이 좋다. 대신 **단순한 부분을 단순하지 않게 연출하는 것**이 중요하다. 도트 애니메이션, 음악, 연출 타이밍을 바꾸며 노력했다.

즉 **디테일이 아니라 연출로 승부**했다는 뜻이다. 우리가 가야 할 방향도 이쪽이다.

## 1-2. 레퍼런스는 3층으로 나눠서 잡기

한 덩어리로 "이런 느낌"이라고 잡으면 반드시 위의 함정에 빠진다. 세 종류로 쪼갠다.

### Layer 1. 무드 레퍼런스 — "어떤 감정인가"
게임이 아니어도 된다. 영화 스틸컷, 사진, 그림, 실제 공간 사진 다 된다.

우리 프로젝트 기준:
- 현실세계: 고인의 집, 유품, 정적인 공간. 온도감?
- 사령세계: 죽음 이후의 공간. 무섭나, 슬프나, 고요한가?

산나비 팀은 사이버펑크 무드를 잡을 때 **신촌의 복잡하게 얽힌 전선, 네온사인, 지저분한 골목**에서 출발했다. 게임 레퍼런스가 아니라 실제 동네였다. 거기에 "낡은 미래"라는 시대 설정과 조선이라는 공간을 덧입혔다.

> 정인이 액션: **게임 스크린샷 말고 사진부터 모아라.** 실제 장례식장, 오래된 집, 유품 정리 현장 같은 것.

### Layer 2. 스타일 레퍼런스 — "어떤 규칙인가"
여기가 진짜 픽셀아트 레퍼런스다. 그런데 **"예쁘다"로 모으면 안 되고 "규칙이 보인다"로 모아야 한다.**

각 레퍼런스에서 뽑아낼 것:

| 항목 | 확인할 것 |
|---|---|
| 스프라이트 높이 | 캐릭터가 화면 세로의 몇 분의 1인가 |
| 아웃라인 | 검정? 컬러? 없음? 부분적? |
| 셰이딩 단계 | 색 하나당 명암을 몇 단계 쓰나 |
| 팔레트 규모 | 한 화면에 몇 색이나 보이나 |
| 디더링 | 쓰나 안 쓰나 |
| 얼굴 디테일 | 눈코입이 보이나, 점 두 개인가 |

이걸 표로 정리해두면 나중에 "우리 규칙"을 정할 때 그대로 재료가 된다.

### Layer 3. 안티 레퍼런스 — "이건 안 한다"
**이게 제일 중요하고 제일 자주 빠뜨린다.**

"이건 좋은데 우리는 못 한다" 목록을 명시적으로 만든다.

예시:
- ❌ 하이퍼라이트 드리프터급 배경 밀도 → 전담 아트팀 규모의 작업량
- ❌ 8방향 애니메이션 → 4방향 또는 좌우반전으로 간다
- ❌ 캐릭터별 고유 얼굴 표정 세트 → 대화창 초상화로 대체
- ❌ 프레임 많은 부드러운 애니메이션 → 프레임 적게, 타이밍으로 승부

> 참고: 하이퍼라이트 드리프터, 데드셀, 이스트워드는 모두 **32~128px 이상의 "하이비트" 영역**이고, 전부 **전담 아트팀이 있는 프로젝트**다. 스타일 가이드들이 공통적으로 경고하는 지점이다.

## 1-3. 레퍼런스 수집 실무 규칙

### 모으는 방식
- **한 곳에 모은다**: 노션 갤러리 뷰 하나. 폴더에 흩뿌리지 않는다
- **출처를 적는다**: 게임명 / 어느 장면인지
- **판정을 적는다**: 매 이미지마다 한 줄

각 카드에 이 세 줄만 있으면 된다:
```
게임: [이름]
좋은 점: [구체적으로. "예쁘다" 금지]
우리한테 못 쓸 점: [작업량? 톤 불일치? 스킬?]
```

### 개수
무드보드 이론상으로는 많을수록 좋지만(20~100장 권장), **초기엔 적을수록 좋다.**
- 1차: 게임 3개만. 깊게 뜯어보기
- 2차: 규칙이 잡힌 뒤 확장

### 레퍼런스는 "정답"이 아니라 "질문"이다
레퍼런스를 보고 "이렇게 그려야지"가 아니라 **"우리는 여기서 뭘 가져오고 뭘 버리지?"**를 물어야 한다.

# PART 2. 작은 것부터 어떻게 올라갈 것인가

## 2-1. 왜 캐릭터부터 그리면 안 되는가

본능적으로는 주인공부터 그리고 싶다. 근데 이게 함정이다.

주인공 스프라이트는:
- 게임에서 가장 오래 보이는 에셋 (= 심리적 압박 최대)
- 애니메이션이 가장 많이 붙는 에셋 (= 작업량 최대)
- 아직 아무 규칙도 안 정해진 상태에서 그리게 됨 (= 재작업 확률 최대)

**압박 최대 × 작업량 최대 × 재작업 최대.** 여기서 시작하면 당연히 막힌다.

## 2-2. 난이도 사다리

작은 것부터 올라가되, "작다"의 기준은 **크기가 아니라 결정 부담**이다.

```
STEP 0  단일 타일 (32x32 벽/바닥 1장)
   ↓    결정할 것: 팔레트, 광원 방향, 텍스처 밀도

STEP 1  타일 세트 (같은 재질 4~6장)
   ↓    결정할 것: 타일 간 연결 규칙, 반복 시 패턴 티 안 나게

STEP 2  소품 오브젝트 (유품 아이템 3~5개)
   ↓    결정할 것: 아웃라인 규칙, 실루엣 가독성
   ★    ← 우리 프로젝트에선 여기가 특별히 중요

STEP 3  UI 아이콘 (인벤토리, 추리보드 슬롯)
   ↓    결정할 것: 저해상도에서 의미 전달

STEP 4  정지 캐릭터 1장 (idle 1프레임)
   ↓    결정할 것: 비율, 얼굴 표현 수준, 실루엣

STEP 5  캐릭터 애니메이션 (idle → walk)
   ↓    결정할 것: 프레임 수, 타이밍

STEP 6  배경 씬 1개 (타일 + 소품 + 캐릭터 합성)
        결정할 것: 전체가 한 화면에서 어울리는가
```

### 왜 이 순서인가
**타일이 1번인 이유**: 실패해도 아무도 안 아프다. 그런데 팔레트·광원·밀도라는 **가장 근본적인 규칙 3개**를 여기서 다 정하게 된다. 가장 싼 값에 가장 비싼 결정을 뽑아내는 구간.

**소품이 캐릭터보다 앞인 이유**: 우리 게임은 **유품이 핵심 게임플레이 오브젝트**다. 챕터당 핵심 유품 3개 + 보조 10~12개. 캐릭터보다 유품이 더 중요할 수도 있는 게임이고, 개수도 많다. 여기서 규칙이 잡히면 나머지가 따라온다.

**배경이 마지막인 이유**: 배경은 앞 단계 결과물의 **조합**이다. 부품 규격이 안 잡혔는데 조립부터 하면 안 된다.

## 2-3. 각 STEP의 "완료" 기준

각 단계마다 **다음으로 넘어가도 되는 조건**을 정해둔다. 안 그러면 STEP 0에서 3주 보낸다.

### STEP 0 완료 조건
- [ ] 타일 1장이 32x32(또는 확정 그리드) 안에 들어감
- [ ] 사용한 색이 팔레트에 등록됨
- [ ] 광원 방향이 좌상단(또는 확정 방향)으로 일관됨
- [ ] 이 타일을 4x4로 반복 배치했을 때 눈에 띄는 패턴이 안 생김
- [ ] **소요 시간을 기록했다** ← 이거 꼭

### STEP 1 완료 조건
- [ ] 타일들이 서로 붙였을 때 이음새가 어색하지 않음
- [ ] 색이 STEP 0 팔레트를 벗어나지 않음
- [ ] 타일 1장당 평균 소요 시간 산출됨

### STEP 2 완료 조건
- [ ] 실루엣만 봤을 때(전부 검정으로 칠했을 때) 뭔지 구분됨
- [ ] 아웃라인 규칙이 3개 다 동일함
- [ ] 게임 화면 크기로 축소했을 때 여전히 식별 가능

### STEP 3 완료 조건
- [ ] 16x16(또는 UI 규격)에서 의미가 읽힘
- [ ] 아이콘끼리 나란히 놨을 때 통일감 있음

### STEP 4 완료 조건
- [ ] 캐릭터 높이가 타일 그리드 대비 명확한 비율 (예: 2타일 높이)
- [ ] 좌우반전했을 때 어색하지 않음 (← 산나비 방식 채택 시 필수)
- [ ] 실루엣만으로 이 캐릭터임이 구분됨

### STEP 5 완료 조건
- [ ] Aseprite에서 재생했을 때 어색하지 않음
- [ ] 유니티에 임포트해서 실제로 움직임
- [ ] **프레임 1장당 소요 시간 산출됨** ← 전체 일정 계산의 근거

### STEP 6 완료 조건
- [ ] 한 화면 안에서 타일/소품/캐릭터의 픽셀 밀도가 튀지 않음
- [ ] 캐릭터가 배경에 묻히지 않음 (가독성)
- [ ] 팀 3명이 봤을 때 "우리 게임 같다"에 동의

## 2-4. 시간 기록이 왜 계속 나오는가

각 STEP마다 "소요 시간 기록"이 반복된다. 이게 이 문서에서 제일 실용적인 부분일 수 있다.

**이유: 챕터1 데모의 실현 가능성을 계산해야 한다.**

```
필요 에셋 추정 (챕터1 기준)
  타일 세트        약 40~60장
  유품 오브젝트    약 15장 (핵심3 + 보조 12)
  UI 아이콘        약 20장
  캐릭터           주인공 1 + NPC 4~5
  캐릭터 애니메    캐릭터당 3~4종 × N프레임
  배경 씬          구역당 1~2
  ─────────────────────────────
  합계             150~250 에셋
```

STEP 0~5에서 나온 **실측 시간**을 여기 곱하면, 2027년 6월 데모가 가능한지 아닌지가 숫자로 나온다.

숫자가 안 맞으면 방법은 셋뿐이다:
1. 스타일을 단순화한다 (해상도↓, 색 수↓, 프레임 수↓)
2. 범위를 줄인다 (구역 수↓, NPC 수↓)
3. 외주를 쓴다 (산나비도 일러스트는 전부 외주였다)

**이 대화를 6개월 뒤가 아니라 지금 하려고 시간을 재는 거다.**

# PART 5. 파일 & 인수인계 규칙

## Aseprite → Unity
유니티에 **Aseprite Importer**가 있다. `.aseprite` 파일을 별도 변환 없이 직접 임포트하면 레이어 구조는 물론 애니메이션 컨트롤러와 클립까지 자동 생성된다. 이전처럼 PNG 수백 장 뽑아서 클립 재조립할 필요 없음.

→ **정인이는 .aseprite만 넘기면 된다.** PNG export 과정 자체가 파이프라인에서 빠진다.

## 유니티 설정 (호윤 담당)
```
Texture Type      : Sprite (2D and UI)
Filter Mode       : Point (no filter)   ← 필수. 안 하면 뿌옇게 됨
Compression       : None
Pixels Per Unit   : 타일 그리드 크기와 동일
```

## 네이밍
```
{world}_{type}_{name}_{state}.aseprite

real_tile_wall_01.aseprite

spirit_char_ghost_idle.aseprite
ui_icon_clue.aseprite
```
