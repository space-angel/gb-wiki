# 첫 스프린트 — 작은 조사 구간 하나를 직접 실행한다

**기간 제안: 2026-09-09~09-22, 2주.** 오늘 회의에서 네 사람의 가용 시간과 첫 결과물을 확인한 뒤 채택합니다. 달력의 2주는 각자가 10일 전일 근무한다는 뜻이 아닙니다.

## 목표와 완료 기준

목표: **“작은 현실 공간에서 물건을 조사하고, NPC의 반응 변화를 확인한 뒤 다시 시작할 수 있다.”**

- 개발자 외 팀원 3명이 같은 빌드와 짧은 실행 안내로 플레이합니다.
- 이동·충돌·조사문 열기/닫기·조사 전후 대화·재시작이 합의한 행동표대로 동작합니다.
- 팀원마다 이해한 변화 한 줄과 막힌 지점을 남깁니다.
- 진행을 막는 오류는 해결하거나, 목표를 축소했다는 합의를 남깁니다. 미해결 차단 오류가 있으면 원래 목표 통과로 기록하지 않습니다.

빌드가 나오지 않고 문서만 준비됐다면 **M0 준비 결과**로 기록합니다. 첫 조사 플레이 M1이 완료된 것은 아닙니다.

## 포함할 작업

공간 1곳, 조사 대상 1개, NPC 1명, 짧은 조사문, 조사 전후 대사, 기본 이동·충돌, 최소 대화 UI, 실험용 상태 초기화, 공유 가능한 시험 빌드입니다.

첫 소재의 권장안은 [오늘 회의](오늘회의.md)에 있습니다. 조사 조건은 실험용 상태로 분리해 적습니다. 정식 이해도 O/A/V/R, 인벤토리·판매·세이브, 사령 전투, 전체 맵, 완성 아트 물량은 이번 완료 조건에 포함하지 않습니다.

## 작업 순서와 담당

| 순서 | 신규 초안 | 담당 제안 | 다음 사람이 받는 것 |
|---|---|---|---|
| 병행 착수 | NS-01 프로젝트 실행·빌드 경로 확인 | 호윤 | 현재 가능한 실행·빌드, 실제 오류, 파일·씬 위치 |
| 병행 착수 | NS-02 첫 실험의 행동·조건·결과표 | 지호 | 동일하게 해석할 입력·반응·종료 기준 |
| 병행 착수 | NS-03 첫 조사문·대사 묶음 | 재화 | 물건·NPC 식별자, 화자·조건·문구 |
| 병행 착수 | NS-04 첫 화면의 공간·UI 러프 | 정인 | 이동 영역·조사 위치·대화 표시와 크기 |
| 입력 확보 후 | NS-05 작은 공간의 이동·조사 빌드 | 호윤 | 실제로 움직이고 조사할 수 있는 빌드 |
| NS-05 후 | NS-06 NPC 반응 변화·재시작 통합 | 호윤 | 처음부터 끝까지 반복 가능한 실험 빌드 |
| NS-06 후 | NS-07 공동 플레이와 다음 단계 판단 | 지호 주관, 전원 참여 | 재현 결과·막힘·통과 또는 수정 결정 |

NS-02~04는 회의에서 고른 동일한 소재로 시작하며 서로의 완성을 기다리지 않습니다. 지호는 조건, 재화는 내용, 정인은 배치를 각각 맡고 중간에 서로 맞춥니다. 검토에서 다른 점이 발견되면 해당 작성자가 수정합니다.

NS-05는 NS-01·02와 조사문이 준비되면 임시 도형으로 진행할 수 있습니다. 정식 아트의 완성을 이동·조사 구현의 선행 조건으로 만들지 않습니다. NS-06에서 전체 텍스트·화면을 맞춥니다.

각 이슈의 상세 범위·완료 조건: [신규 이슈 초안](신규이슈_초안.md).

## 시작할 때 채울 작업량

| 담당 | 실제 가용 시간 | 약속 작업 예상 시간 | 검토·수정 여유 | 합의한 범위 |
|---|---|---|---|---|
| 호윤 | 미정 | NS-01·05·06 합계 미정 | 가용량의 약 30% 제안 | 미정 |
| 지호 | 미정 | NS-02·07 합계 미정 | 가용량의 약 30% 제안 | 미정 |
| 재화 | 미정 | NS-03 및 플레이 후 수정 미정 | 가용량의 약 30% 제안 | 미정 |
| 정인 | 미정 | NS-04 및 빌드 가독성 수정 미정 | 가용량의 약 30% 제안 | 미정 |

시간 추정이 어려우면 본인이 가능한 작업 세션 수와 한 세션 길이로 적습니다. 큰 작업이 본인의 세션 3회를 넘을 것 같으면 결과가 드러나는 경계에서 나누거나 이번 목표를 줄입니다. 세션 3회는 이슈 분할을 검토하는 초기 기준입니다.

**착수 가능한 첫 4건부터 시작합니다.** NS-05~07도 이번 사이클에 약속할 수 있는지 위 표로 확인하고, 선행 조건이 남아 있으면 `할 일`에서 관계를 표시합니다. 약속하지 않은 후보는 사이클 밖 백로그에 둡니다. 전부를 자동으로 2주 약속으로 만들지 않습니다.

## 점검과 막힘 처리

| 시점 제안 | 확인할 것 | 결과에 따른 조정 |
|---|---|---|
| 첫 작업 세션 종료 | 실행 경로·행동표·텍스트·화면의 최소 샘플 | 모르는 항목을 구체 질문으로 만들고 확인 담당 지정 |
| 9/15 중간 확인 | 실제 이동·조사 결과와 통합 예상량 | 아직 실행이 막히면 대화 통합 약속을 재조정 |
| 9/22 공동 플레이 | 목표 재현, 이해한 변화, 진행 오류 | M1 통과 / 제한된 결과만 달성 / 수정 필요 중 하나 기록 |

각자 작업을 마칠 때 `결과 링크 / 다음 행동 / 막힌 것`을 자기 이슈에 갱신합니다. 매일 별도 장문 보고를 작성하지 않습니다.

막히면 이유·도움이 필요한 사람·다음 확인 시점을 적습니다. 해결 전에도 가능한 독립 작업만 진행합니다. 팀 전체 `작업중`은 4건, 개인 `작업중`은 1건을 권장하며, `검토`도 개인당 1건을 넘겨 쌓지 않습니다.

| 항목 | 기입할 내용 |
|---|---|
