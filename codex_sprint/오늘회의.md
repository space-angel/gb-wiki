# 2026-09-08 회의 — 다음에 각자 무엇을 끝낼 것인가

**회의 제안: 50분.** 아래 담당은 과거 역할 기록을 바탕으로 한 제안입니다. 현재 역할·시간·최종 결정권을 오늘 확인합니다. 회의 합의란은 아직 비어 있습니다.

## 시작할 때 공유할 내용

> 현재 플레이 가능한 빌드가 없습니다. ADR은 기준으로 삼고, 나머지 기획은 작업 중인 상태에서 출발합니다. 이번에는 작은 조사 구간 하나를 함께 완성하고 실행해 보겠습니다. 각자 첫 결과물 하나와 그것을 누구에게 언제 전달할지 정합니다. Linear는 새 이슈로 구성하되, 제목과 설명 방식은 먼저 협의합니다.

## 오늘 결정할 다섯 가지

| 시간 | 안건 | 회의에서 남길 결과 |
|---|---|---|

| 5~15분 | 첫 실험 선택 | 아래 권장 범위를 유지할지, 바꿀지와 성공 조건 한 문장 |
| 15~30분 | 네 사람의 첫 약속 | 담당별 첫 결과물, 실제 작업 가능 시간, 다음 확인 시점 |

| 40~50분 | 운영 방식 | 스프린트 기간, 조율 담당, 컨벤션 협의 후 Linear 등록 순서 |

## 첫 실험 권장 범위

**“작은 현실 공간에서 물건 하나를 조사하고, NPC에게 다시 말을 걸어 반응이 달라졌음을 확인한다.”**

구체 후보는 고양이 물그릇과 이유미입니다. 현재 위키에서 연결을 찾을 수 있고, 적은 공간·텍스트로 조사와 대화의 연결을 확인할 수 있어서 권장합니다. **물그릇 1회 조사로 대사가 바뀐다는 조건은 이번 실험의 제안**입니다. 정식 챕터 해금 규칙이나 O/A/V/R 판정으로 확정하지 않습니다.

오늘 다른 소재를 선택해도 `작은 공간 1곳 / 조사 대상 1개 / NPC 1명 / 조사 전후 반응 / 다시 시작`이라는 작업 크기는 유지합니다. 미래축을 선택하면 상담사 대본의 한 대화 묶음만 사용합니다. 미래축 전체·사령세계·회상 전체는 별도 단계입니다.

첫 실험이 끝나면 곧바로 **정보를 연결해 해석이 바뀌는 추리 실험**으로 넘어갈지를 판단합니다. 첫 빌드만으로 게임의 재미나 핵심 추리가 검증됐다고 기록하지 않습니다.

근거: [NPC](../codex_wiki/02_스토리_캐릭터/NPC.md), [조사축](../codex_wiki/03_조사_추리_진행/조사축.md), [단계별 로드맵](로드맵.md).

## 각 인원의 집중 작업

| 담당 제안 | 가장 먼저 끝낼 것 | 전달할 결과와 받는 사람 | 그다음 집중할 것 |
|---|---|---|---|
| **송호윤 — 개발·통합** | 실제 프로젝트를 열어 실행·빌드 경로 확인 · NS-01 | 실행 방법, 현재 동작·오류, 시험 빌드 또는 구체적 차단 원인 → 전원 | NS-05 이동·조사 → NS-06 대화 변화·재시작. 순서대로 진행 |
| **안지호 — 규칙·검증** | 첫 실험의 행동·조건·결과표 · NS-02 | 무엇을 누르면 무엇이 달라지는지와 성공/실패 사례 → 호윤·재화·정인 | NS-07 공동 플레이 검토. 통과 후 다음 추리 구간의 규칙 NS-08 |
| **이재화 — 스토리·콘텐츠** | 선택한 대상의 조사문과 NPC 조사 전후 대사 · NS-03 | 화자·공개 조건·실제 문구를 연결한 짧은 묶음 → 지호·호윤 | 플레이에서 오해한 부분 수정. 통과 후 해석 변화와 증거 구성 NS-09 |
| **문정인 — 아트·UI** | 한 화면의 동선·조사 대상·대화창 배치 러프 · NS-04 | 이동 가능 영역, 물건·NPC 위치, 표시 크기와 원본 → 재화·호윤 | 빌드에서 가독성·충돌 표시 확인, 필요한 부분만 수정 |

첫 네 작업의 상세 완료 기준은 [신규 이슈 NS-01~04](신규이슈_초안.md)에 있습니다. 회의가 끝나면 각자 자기 이슈의 결과물·예상 작업량을 직접 확인합니다.

### 개발에 일이 몰리지 않게 나누는 책임

- 지호: 이번 실험의 범위와 게임 조건 조율을 제안합니다. 규칙 변경이 필요한 경우 관련 ADR과 문서를 함께 정리합니다.
- 재화: 실제 쓸 텍스트와 화자·조건을 직접 정리합니다. 호윤이 원문을 읽고 대본을 다시 만드는 업무는 잡지 않습니다.
- 정인: 크기·레이어·파일 위치를 포함해 전달합니다. 게임에 넣어 본 뒤 필요한 수정에 집중합니다.
- 호윤: 구현 가능성과 입력 형식의 최소 조건을 설명하고, 통합 결과를 만듭니다.
- 각자: 자기 상태·막힘·결과 링크를 직접 갱신합니다. 회의 조율 담당이 네 사람의 업무를 대신 작성하지 않습니다.

문서·텍스트·그림 검토는 받는 사람이 맡습니다. 구현 검토는 지호가 진행하고 나머지 두 사람도 직접 실행합니다. 담당자 부재로 하루 이상 지연되면 다음 가능한 확인 시점을 정하고 범위를 줄입니다. 하루 기준은 응답을 재촉하는 기한이 아니라 막힘을 드러내는 점검 기준입니다.

## 작업량을 정하는 방법

각자가 다음 2주에 실제로 쓸 수 있는 시간을 먼저 적습니다. 그중 **약 70%까지만 약속 작업**으로 잡고, 나머지는 검토·통합 오류·수정 여유로 둡니다. 70%는 초기 운영 제안이며 실제 소요를 보고 조정합니다.

특히 호윤의 `프로젝트 확인 + 이동·조사 + 대화 통합`이 본인 가용량을 넘으면, 첫 약속을 이동·조사까지 줄입니다. 다른 사람의 여유 시간으로 개발 시간을 대신 계산하지 않습니다. 대화 변화 목표는 다음 사이클로 명시적으로 이동합니다.
