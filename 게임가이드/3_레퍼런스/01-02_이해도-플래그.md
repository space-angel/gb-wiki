> **한 줄**: 이해도는 **O→A→V→R 4개의 boolean**이다. 단일 수치도 가중 합산도 아니며, **이전 플래그가 true여야 다음 달성이 가능**하다.

# 이해도 내부 표현 — 4종 이산 플래그

## 자료 구조

```
O_reached → A_reached → V_reached → R_reached
 (관찰)       (연결)       (검증)      (재해석)
```

| 플래그 | 이름 | 현실세계 행동 |
|---|---|---|
| `O_reached` | 관찰 | 탐색, 아이템 획득 |
| `A_reached` | 연결 | 보드 연결, 가설 선택 |
| `V_reached` | 검증 | NPC 대화, 교차검증 |
| `R_reached` | 재해석 | 핵심 아이템 보드 연결 |

**순서 의존적**: 이전 플래그가 true여야 다음 플래그 달성이 가능하다.

## 절대 규칙 4가지

1. **이해도를 단일 수치·가중 합산으로 표현하지 않는다.** (`U = 0.1·O + 0.2·A + …` 형태 금지)
2. **순서 의존성을 깨는 트리거를 만들지 않는다.** (예: O 없이 A 달성)
3. **보스 도전 가능 시점을 이해도 플래그에 종속시키지 않는다.** 보스 도전은 O_reached 시점부터 항상 가능하다.
4. **5단계 이상으로 늘리지 않는다.** 서사적으로 필요한 중간 비트(예: "기대가 부담이 됨")는 **연출 비트**로 처리하고 플래그로 신설하지 않는다.

## 왜 이렇게 정했나

가중 합산을 버린 이유(**R=0이어도 성불에 도달할 수 있다**)와 기각한 대안 3가지는 심화 문서에 있어요.

→ **[왜 4플래그인가](../4_심화/왜-4플래그인가.md)**

가중치·수치 논의가 다시 올라오면 그 문서의 "다시 논의될 때 확인할 것"을 먼저 보세요.

## 제약

- 플레이어 진행 표현이 이산적이다. "지금 60%쯤 왔다" 같은 중간 표현 불가. 단 `01-01`이 어차피 수치 비노출을 명시하므로 실질 손실은 없다
- 플래그 간 가중치를 통한 미세 조정이 불가능하다
