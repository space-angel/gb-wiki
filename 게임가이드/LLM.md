# 에이전트 진입점 — 먼저 읽을 것

사령 게임(ATK_DEF) 챕터1 설계 문서 트리. **이 파일을 항상 컨텍스트에 넣는다.**

## 읽는 순서

```
LLM.md (이 파일) → 1_소개/전체_요약.md → 라우팅 표에서 해당 파일 1~2개
```

전체를 읽지 않는다. `전체_요약.md`는 항상 로드해도 될 크기이고, 세부는 라우팅 표로 좁힌다.

**사람용 진입점은 다르다.** 사람이 물으면 `README.md` 또는 `2_가이드/시작하기.md`로 안내한다.

---

## 1. 상태를 먼저 본다

모든 파일 frontmatter와 각 주장에 상태가 붙어 있다.

| 상태 | 뜻 | 답할 때 |
|---|---|---|
| `확정` | ADR로 팀 합의 완료 (Accepted) | 그대로 답한다 |
| `잠정` | 제안 상태(Proposed)이거나 한 사람이 정함 | **"잠정입니다"를 반드시 붙인다** |
| `미정` | 아직 결정되지 않음 | **"아직 없습니다"라고 답한다. 추측해서 채우지 않는다** |
| `검토필요` | 문서 간 서술이 갈림 | **한쪽을 고르지 않는다.** 양쪽을 보여주고 `06-03`을 안내한다 |

### `검토필요`를 만나면

한쪽이 더 그럴듯해 보여도 고르지 않는다. 이렇게 답한다:

> "메인 유품 3종은 문서마다 다릅니다. 최신 스토리 문서(08-04)는 졸업사진/핸드폰/취준파일이고, ADR-13(07-20, Proposed)은 졸업사진액자/파일철/고양이이동장입니다. 아직 정리되지 않은 항목입니다. (`04-05`, `06-03`)"

**"ADR에 있으니 이게 맞다"고 판단하지 않는다.** ADR-11·12·13·14는 Proposed라 확정 효력이 없다.

---

## 2. 인용 규칙

- 답변에 **파일 ID**를 명시한다. 예: `(01-05)`, `(04-04)`
- 근거 ADR이 있으면 함께: `(01-05, ADR-3)`
- 트리에서 못 찾으면 **"문서에 없습니다"** 라고 답한다. 그럴듯하게 채우지 않는다

---

## 3. 라우팅 표 — 질문 → 파일

### 소개 · 가이드 (사람이 물을 때)

| 질문 유형 | 파일 |
|---|---|
| 이 게임 뭐야 / 어떤 게임이야 | `1_소개/개요.md` |
| 왜 이렇게 설계했어 / 설계 원칙 | `1_소개/핵심원칙.md` |
| 뭐부터 읽어야 해 / 온보딩 | `2_가이드/시작하기.md` |
| 나(스토리/시스템/아트/개발)는 뭘 봐야 해 | `2_가이드/내_파트_찾기.md` |
| 이 배지 무슨 뜻이야 / 문서 규칙 | `2_가이드/문서_규칙.md` |

### 심화 — "왜 그렇게 정했나"

**레퍼런스는 "무엇"만 다룬다. "왜"를 물으면 반드시 심화로 보낸다.**

| 질문 유형 | 파일 |
|---|---|
| 왜 4플래그야 / 가중치 쓰면 안 돼? | `4_심화/왜-4플래그인가.md` |
| 왜 패링 없어 / 방어 추가하면 안 돼? | `4_심화/왜-회피만인가.md` |
| 왜 등급이 2개뿐이야 / 늘리면 안 돼? | `4_심화/왜-판매여부가-위계인가.md` |
| 왜 보스방이 따로야 / 진행 게이트 걸면 안 돼? | `4_심화/왜-보스방을-분리했나.md` |
| 왜 이해도 게이지가 없어 / UI로 보여주면 안 돼? | `4_심화/왜-이해도를-안보여주나.md` |

> 위 5개 질문은 **팀에서 반복적으로 재발한 논의**다. 각 문서의 "다시 논의될 때 확인할 것" 섹션을 반드시 함께 인용한다.

### 시스템

## 4. 하지 않는 것

- **추측해서 채우지 않는다.** 이 프로젝트는 이미 "그럴듯한 옛 버전"이 여기저기 남아 생긴 문제를 겪는 중이다
- **`검토필요` 항목에서 한쪽을 고르지 않는다**
- **스스로 결론 내지 않는다.** 새 충돌을 발견하면 해결하지 말고 "`06-03`에 추가해야 할 사안으로 보입니다"라고 안내한다
- **갱신일이 2주 이상 지났으면** 답변 끝에 한 줄 붙인다: *"이 문서는 N주 전 기준입니다."*

## 5. 이 트리 밖

| 소스 | 언제 쓰나 |
|---|---|
| `gb_wiki/raw/00_컴플라이언스/ADR/` | ADR 원문. **"왜 그렇게 정했나"와 "기각된 대안"** 을 물을 때 |
| `gb_wiki/raw/` | 이 트리에 없는 세부가 필요할 때 (ADR 감사 결과: `raw/03_진단문서/ADR_감사_결과_0805.md`) |
| `gb_wiki/raw/01_확정레퍼런스_후보/캐릭터_스토리/챕터1_최신본/` | 스토리 원본 정리본 |
| `gb_wiki/게임시스템_확정본/` | ADR→시스템 명세 재구성본 |
| Notion (Z-B 샌드박스) | 최신 원본. **어수선한 게 정상** |

> **ADR 원문 인용 시 주의**: supersede가 원문에 반영돼 있지 않다. ADR-1은 출력 3종을 정의했지만 ADR-9가 하나를 삭제했고 본문은 그대로다. **이 트리는 이미 반영했으므로 트리를 따른다.**

## 6. 파일 형식

모든 파일은 동일한 구조다.

```yaml
---
id: 01-02
제목: …
상태: 확정 | 잠정 | 미정 | 검토필요
근거: [ADR-2]
담당: 지호
갱신일: 2026-08-05
키워드: [검색용 키워드]
관련: [연관 파일 id]
---

> **한 줄**: 가장 자주 묻는 질문에 대한 한 문장 답

(본문)
```

`> **한 줄**` 은 조각 검색만으로도 정답이 나오게 하기 위한 것이다. 이것만 읽고 답해도 틀리지 않아야 한다.
