> **한 줄**: 가중 합산을 쓰면 **재해석 없이도 성불에 도달할 수 있어요.** 4개 boolean의 AND는 그걸 데이터 구조 자체로 막아요. 이게 결정적인 이유였어요.

# 왜 4플래그인가

## 무엇이 문제였나

2026-06-15 이전엔 이해도를 **어떤 자료형으로 표현할지**가 안 정해져 있었어요. 정의와 출력(ADR-1)은 잠겼는데 내부 표현이 비어 있어서, 그 위에 얹을 작업이 다 멈춰 있었죠.

두 모델이 경합했어요.

**가중 합산 스칼라** — 행위별로 가중치를 줘서 하나의 수치로 합쳐요.
```
U = 0.1·O + 0.2·A + 0.3·V + 0.4·R
```
익숙하고, 임계값으로 분기하기 쉬워요.

**4종 이산 플래그** — 관찰(O)·연결(A)·검증(V)·재해석(R)을 각각 boolean으로 두고 순서대로 진행해요.

문제는 **아무것도 안 정해진 상태에서 지호의 메카닉 문서가 가중 합산을 잠정 가정하고 작성되고 있었다**는 거예요. 이대로 두면 입력 행위별 가중치 수치를 정해야 하고, 임계값 컷오프 수치도 정해야 하고, 그게 다 Phase 0 작업량으로 불어나요.

## 검토한 대안

| 대안 | 장점 | 기각 사유 |
|---|---|---|
| **가중 합산 스칼라** | 익숙함. 임계값 분기가 쉬움. 중간 진행도 표현 가능 | **R=0이어도 성불 가능** ← 아래 참조 |
| **단일 수치 (0~100)** | 가장 단순 | 측정 의미가 약함. 수치가 왜 변했는지를 작가가 일일이 설계해야 함 |
| **5단계 이상 플래그** | 서사적으로 더 촘촘함 | 게임 플로우와 1:1 대응이 깨짐. 작가·구현 부담 증가 |
| **4종 이산 플래그** ✅ | 아래 | — |

## 채택한 이유 — 한 가지가 결정적이었어요

가중 합산 모델에는 이런 구멍이 있어요.

> `U = 0.1·O + 0.2·A + 0.3·V + 0.4·R` 에서 **R이 0이어도** O·A·V의 합만으로 성불 임계값에 도달할 수 있어요.
>
> 즉 **"재해석 없이 성불"** 이 이론상 성립해요.

그런데 ADR-1이 정한 이 게임의 핵심은 **"재해석이 종결의 핵심"** 이에요. 가중 합산을 쓰면 그 원칙이 **수치 조정으로 언제든 깨질 수 있는 것**이 돼요. 누군가 밸런싱하다가 가중치를 만지면 조용히 무너져요.

4개 boolean의 AND는 이걸 **데이터 구조 자체로 차단**해요. R이 false면 성불 조건이 애초에 성립하지 않아요. 밸런싱으로 뚫을 방법이 없어요.

> **원칙을 문서로 지키는 것과 자료구조로 지키는 것은 다릅니다.** 이 결정은 후자를 택한 거예요.

### 부수 효과 (이것 때문에 택한 건 아니에요)

- 가중치 수치 설계가 **불필요**해져요
- 임계값 컷오프 수치 결정도 **불필요**해져요
- 구현이 bool 4개 체크로 끝나요. ScriptableObject·세이브 파일·이벤트 시스템이 다 단순해져요
- 파이프라인이 게임 플로우와 1:1 대응해요 (탐색→추리→검증→재해석)

## 대신 감당하는 것

- **중간 진행도를 표현할 수 없어요.** "지금 60%쯤 왔다" 같은 게 불가능해요.
  → 단 ADR-1이 어차피 **수치 비노출**을 명시하니 실질 손실은 없어요.
- **플래그 간 가중치로 미세 조정을 못 해요.** 디자인을 바꾸려면 트리거 조건을 수정해야 해요.
- **종합 이해도 U(챕터 합산) 산출이 더 복잡해져요.** boolean 4개를 챕터별로 어떻게 합산할지 별도 설계가 필요해요. (아직 미결 → `06-02`)

## 다시 논의될 때 확인할 것

가중치·수치 이야기가 다시 올라오면 **이 문장 하나만 먼저 확인하세요.**

> **"이 방식에서 R 없이 성불이 가능한가?"**

가능하다면 그 안은 ADR-2를 supersede해야 해요. 조용히 도입하면 안 돼요.
