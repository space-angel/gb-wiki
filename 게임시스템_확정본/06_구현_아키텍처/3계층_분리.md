# ⚠️ 3계층 시스템 분리 — 인벤토리 / 플래그 / 컷씬 (미확정)

> **Proposed 상태.** 2026-07-20 논의에서 도출, 안지호 최종 확인 대기.
> 이 문서는 **구현 아키텍처 결정**이다. 개발 초기부터 지켜야 의미가 있으므로, Unity 작업 시작 전 확정 여부를 확인할 것.

## 문제 — 왜 이 결정이 필요했나

세 가지가 개별적으로는 다 옳은데 동시에 만족시키려니 충돌했다.

- 메인유품 **자유 획득** (재화 물품 후보 문서)
- 사령세계 **구역 개방은 추리와 무관** ([[공간_개방_규칙]])
- 이해도 **O/A/V/R 순차 진행** ([[이해도_4플래그_파이프라인]])

아이템을 초반에 자유롭게 다 주울 수 있게 하면 순서의존이 깨지고, 순서를 지키려 획득을 제한하면 자유 획득 원칙과 부딪힌다.

**근본 원인**: "아이템을 가지고 있다"와 "이야기가 진행됐다"를 **하나의 상태로 취급**한 것. 아이템 소지 여부로 플래그를 직접 판정하면 순서를 건너뛸 수 있다.

## 해법 — 3개의 독립 계층

| 계층 | 담당 | **하지 않는 일** |
|---|---|---|
| **인벤토리** | 무엇을, 몇 개 보유 중인지 기록 | 무엇을 주웠는지는 판단하지 않음 (개수만 셈) |
| **플래그** | O/A/V/R 네 조건의 참/거짓만 판정 | 대사·컷씬을 직접 재생하지 않음 |
| **컷씬** | 플래그가 방금 참이 됐다는 **신호**를 받아 연출만 실행 | 조건을 스스로 판단하지 않음, 인벤토리를 직접 조회하지 않음 |

## 참조 방향 제약 — 이게 핵심

```
인벤토리 ──[임계값 초과 이벤트]──> 플래그 ──[참 신호]──> 컷씬
   ▲                                                      │
   └────────── 직접 조회 금지 (역방향 참조 없음) ──────────┘
```

- 인벤토리는 플래그 상태를 **직접 변경하지 않는다.** "카운트가 임계값을 넘었다"는 **이벤트만 발행**한다.
- 컷씬은 인벤토리를 **직접 조회하지 않고**, 오직 플래그의 참 신호만 구독한다.
- **O 이후(A/V/R)는 인벤토리 이벤트를 아예 구독하지 않는다.**

## 단계별 계층 동작

| 단계 | 인벤토리가 보는 것 | 플래그 판정 | 컷씬이 여는 것 |
|---|---|---|---|
| **O** | 보조유품 보유 개수 (판매분 제외) | N개 이상 → TRUE | 핵심유품 제시 상호작용 활성화 |
| **A** | *(참조 안 함)* | 유품 제시 완료 → TRUE | 사령세계 회상 공간 진입 가능 |
| **V** | *(참조 안 함)* | 회상 확인 완료 → TRUE | 재구성보드 전체 단서 공개 |
| **R** | *(참조 안 함)* | 4슬롯 충족 + 가설 정답 → TRUE | 엔딩 분기 컷씬 |

## 아이템별 계층 역할 (ADR-13 기재)

| 아이템 | 계층상 역할 | 비고 |
|---|---|---|
| 졸업사진 액자 (메인A) | 열쇠. 1구역 + 보스방 개방 | 인벤토리엔 보유 여부만 |
| 취업 준비 파일철 (메인B) | 열쇠. 2구역 개방 | 획득 위치: 사령 1구역 (ADR-11 정합) |
| 고양이 이동장 (메인C) | 열쇠. 3구역 개방 | 획득 위치: 현실 숨은장소 (암호 해금) |
| 인턴 출입증 | 보조. O카운트+1, 판매가능 | 메인B와 페어링 |
| 낡은 러닝화 | 보조. O카운트+1, 판매가능 | 메인C와 페어링 |
| (미정 4개) | 보조. O카운트+1, 판매가능 | 메인A 페어링 2개 + 메인B/C 각 1개 |

> 🔴 **이 아이템 목록이 최신 스토리 자료와 다르다.** 스토리 쪽 메인 3종은 졸업사진 / **핸드폰** / 취준 파일이며 고양이 이동장은 보조로 분류된다. → [[공간_개방_규칙]]의 "스토리 자료와의 근본적 충돌" 참조.

**페어링 주의**: 보조유품·메인유품의 "페어링"은 **배치 레이어일 뿐**, 시스템적 해금 의존 관계를 만들지 않는다.

## 준수 사항 (확정 시 적용될 것)

1. 인벤토리 모듈은 **카운트 기록과 임계값 이벤트 발행만** 한다.
2. 플래그 모듈은 **조건 판정만** 하며, 대사·컷씬을 직접 재생하지 않는다.
3. 컷씬 모듈은 **플래그의 참 신호만 구독**하며, 인벤토리를 직접 참조하지 않는다.
4. **O 이후(A/V/R) 판정 로직은 인벤토리 이벤트를 구독하지 않는다.**
5. 보조유품의 서사적 페어링은 **배치 위치로만** 구현하며, 해금 조건에 포함하지 않는다.

## 비용 / 리스크
- **계층 간 참조 방향을 개발 초기부터 엄격히 지켜야 한다.** 우회 구현 한 번이면 이 ADR은 무력화된다.
- "보조유품 페어링(서사)"과 "시스템 의존(게이트)"의 구분을 작가와 반복 커뮤니케이션해야 한다.

## 미해결 항목 (ADR 원문 OQ)

| OQ | 내용 |
|---|---|
| OQ-1 | 메인A 페어링 보조 2개, 메인B/C 각 1개 (총 4개) 신규 설계 필요 |
| OQ-2 | 파일철·이동장 획득 위치를 ADR-11 체이닝 구조에 맞춰 재화 문서 재작성 필요 |

## 기각된 대안

| 대안 | 기각 사유 |
|---|---|
| 아이템 소지 여부로 플래그 직접 판정 | 순서의존 위반 가능 |
| 인벤토리·플래그·컷씬 단일 모듈 통합 | 유지보수 비용 급증 |
