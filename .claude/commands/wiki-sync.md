# /wiki-sync — 위키 대조·갱신 파이프라인

`게임가이드/`는 파생 읽기 층(derived read model)이다. 진실의 원천은 Notion(팀원 각자 샌드박스)과
`raw/`다. 이 커맨드가 따르는 원칙은 **"에이전트가 대조·갱신 → 사람은 🔴 갈림만 해소"** 다. 사람에게
새로 시키는 일을 만들지 않는다. 갈림(🔴)을 발견해도 판단하지 않고 보고만 한다. ❌ 위반은 확정 ADR이
이미 답을 갖고 있으므로 에이전트가 직접 고친다 — 회의도, 사람의 승인도 필요 없다.

인자로 범위가 주어지면(`/wiki-sync 이해도`, `/wiki-sync 06-03`) 그 주제/파일만 대조한다. 인자가
없으면 전체를 돈다.

**실행 모드**: 사람이 대화형으로 실행하면 Stage 3는 텍스트로만 출력한다(§Stage 3 참고). 스케줄러가
무인으로 실행하면(`실행모드: 스케줄` 인자) Stage 3는 대신 Notion에 로그 페이지를 쓰고, 끝에
`raw/`·`게임가이드/` 변경분을 커밋·push까지 한다 — 지켜보는 사람이 없기 때문이다.

---

## Stage 0 — 원천 흡수 (Notion → raw)

1. `raw/00_컴플라이언스/노션_위치_지도.md`를 읽는다 — 팀원 샌드박스 위치, ADR/트래커 DB 중복 현황,
   변경 감지에 쓸 `ATK_DEF 라이브러리` Wiki DB 좌표가 여기 있다.
2. `raw/03_진단문서/마지막_동기화.md`에서 마지막 동기화 시점을 읽는다.
3. `notion-query-data-sources`로 위치 지도 §1의 SQL을 돌려, 마지막 동기화 시점 이후 `최종 편집
   일시`가 찍힌 페이지 전체를 한 번에 가져온다(샌드박스를 하나씩 방문할 필요 없음). 결과의 각 행을
   위치 지도 §2 표로 어느 팀원·어느 raw 폴더 대응인지 매핑한다. 표에 없는 새 패턴이면 이번 Stage 3
   보고에 "미분류"로 명시한다 — 추측으로 폴더를 정하지 않는다.
4. `raw/00_컴플라이언스/ADR`·`raw/04_회의록`도 같은 시점 기준으로 신규/Accepted 전환 여부를 확인한다.
5. 변경/신규 발견 시 해당 내용을 **`raw/`에 대응 폴더로 반영**한다(원문 그대로 스냅샷, 가공하지
   않음). 새 회의록은 `raw/04_회의록/YYYY-MM-DD_제목.md` 형식.
6. Notion MCP로 확인이 안 되는 범위(권한 밖 페이지 등)는 건너뛰고 **Stage 3 보고에 명시**한다 —
   "확인 못 함"과 "변경 없음"을 구분해서 적는다. 조용히 넘어가지 않는다.
7. Stage 3를 마친 뒤 `raw/03_진단문서/마지막_동기화.md`의 "마지막 동기화" 값을 이번 실행 시각으로
   갱신하고, 이력 표에 한 줄 추가한다.

## Stage 1 — 대조

1. 먼저 ADR의 supersede 관계를 파악한다. `raw/00_컴플라이언스/ADR/*` 전체를 읽고 Accepted/Proposed
   상태와, 뒤 번호 ADR이 앞 번호 ADR의 일부를 폐기한 케이스(예: ADR-9가 ADR-1 출력 3종 중 하나
   삭제)를 정리한다. **Proposed는 확정 효력이 없다** — "ADR에 있으니 맞다"고 판단하지 않는다.
2. `게임가이드/3_레퍼런스`, `4_심화`, `5_예제`, `6_현황`의 각 파일을 frontmatter의 `근거`(ADR 번호)와
   `관련` 필드를 따라가며, 대응하는 소스와 문장 단위로 대조한다:
   - 1차 소스: `게임시스템_확정본/`, `raw/01_확정레퍼런스_후보/캐릭터_스토리/챕터1_최신본/` (게임가이드가 직접 파생된 곳)
   - 근거 원장: `raw/00_컴플라이언스/ADR`, `raw/00_컴플라이언스/트래커`
   - Stage 0에서 갱신된 `raw/01_확정레퍼런스_후보`, `02_참고자료_후보`
3. 각 페이지의 각 주장을 아래 3가지 중 하나로 분류한다. **문서 단위가 아니라 주장(문장) 단위로
   판정한다** — 한 문서 안에 확정과 미확정이 섞여 있을 수 있다(`00_위키_설계.md` 원칙 2).

   | 분류 | 조건 | 처리 |
   |---|---|---|
   | 동일 | 소스와 일치 | `확인일`만 갱신 |
   | ❌ 위반 | 확정(Accepted) ADR이 있는데 게임가이드 또는 소스 쪽 문서가 어김 | Stage 2에서 직접 고침 |
   | 🔴 갈림 | 심판할 확정 결정이 없다(Proposed끼리 충돌, 또는 소스 간 최신 시점이 불명확) | Stage 2에서 `06-03`에 추가만. **고르지 않는다** |

4. 최신 시점 판단이 필요하면(예: 같은 작성자가 사흘 간격으로 다른 답을 낸 케이스) **더 나중에 쓰인
   쪽을 최신으로 잠정 표시**하되, 그것만으로 🟢 확정 처리하지 않는다 — 시점상 최신일 뿐 팀 합의는
   아니므로 🟡 잠정 또는 기존 갈림 유지.

## Stage 2 — 게임가이드 갱신

1. **위반 수정**: 확정 ADR을 어기는 `게임가이드/` 문서를 직접 고친다. 고친 문서의 `갱신일`을 오늘
   날짜로 바꾼다. `6_현황/06-03_검토-필요.md`의 "❌ 위반" 표에서 해당 행을 제거한다.
2. **확인일 갱신**: 대조를 마친 모든 파일의 frontmatter `확인일`(또는 `갱신일`)을 오늘 날짜로
   갱신한다. 내용을 바꾸지 않았어도 대조는 했으므로 갱신한다.
3. **새 갈림 등록**: Stage 1에서 새로 발견한 갈림을 `06-03`의 "🔴 갈림" 표에 기존 형식(안/출처/주장,
   왜 갈렸나, 막고 있는 것, 정할 사람)으로 추가한다. **에이전트가 안을 고르지 않는다.**
4. **해소된 갈림 반영**: `06-03`에 있던 갈림이 이번 대조에서 확정 ADR로 잠긴 게 확인되면(사람이
   회의로 해소하고 ADR을 Accepted로 등록한 경우), 해당 문서의 `상태`를 `확정`/`잠정`으로 바꾸고
   `06-03`에서 제거한다.
5. `6_현황/06-02_미결-항목.md`도 같은 방식으로 트래커 최신 상태와 대조해 갱신한다.
6. `게임가이드/README.md`의 "기준일"과 `게임가이드/LLM.md`의 "갱신일"을 오늘 날짜로 갱신한다.

## Stage 3 — 보고 (사람 몫 안내)

작업이 끝나면 다음 형식으로 요약한다.

```
## 위키 동기화 결과 (YYYY-MM-DD)

- Stage 0: [Notion에서 확인한 변경 N건 / 확인 못 한 범위 / 미분류 N건]
- 위반 수정: N건 (파일명 나열)
- 확인일만 갱신: N건
- 새로 발견한 갈림: N건 (06-03에 추가됨, 목록)
- 해소되어 제거한 갈림: N건

**사람이 할 일은 아래뿐**:
- [06-03의 🔴 갈림 목록 — 정할 사람과 함께]
```

- 갈림이 하나도 없으면 "🔴 없음 — 지금 회의 안건 없음"이라고 명시한다.
- 이번 대조에서 아무것도 못 바꿨다면(Stage 0 확인 실패 등) 그 사실과 원인을 숨기지 않고 보고한다.
  **"조용히 틀리지 않고 시끄럽게 낡는다"**가 원칙이다.

**대화형 실행**: 위 형식을 텍스트로 출력한다. 별도 문서를 새로 만들지 않는다.

**스케줄 실행** (`실행모드: 스케줄`): 텍스트 출력 대신 Notion `컴플라이언스` 페이지
(`raw/00_컴플라이언스/노션_위치_지도.md`에 좌표 있음) 하위에 `notion-create-pages`로 새 페이지를
만든다 — 제목 `위키 동기화 로그 YYYY-MM-DD`, 본문은 위 형식 그대로. Slack에 아직 자동 포스팅 수단이
없어서 팀원이 평소 여는 Notion을 대신 씀 — Slack 봇에 push 기능이 생기면 이 단계를 대체한다. 이어서
`raw/`·`게임가이드/`에 실제로 바뀐 파일이 있으면 커밋하고 `origin main`에 push한다. 커밋 메시지에는
이번 실행에서 고친 위반 건수와 새로 등록된 갈림 건수를 요약해 적는다. 위반 수정 이외의 판단(갈림 중
하나를 고르는 것, `raw/` 폴더 구조를 새로 만드는 것)은 스케줄 실행에서도 여전히 금지다.

## 하지 않는 것 (LLM.md §4와 동일한 원칙)

- 추측해서 채우지 않는다. 소스에 없으면 위키에도 안 넣는다.
- 🔴 갈림에서 한쪽을 골라 조용히 확정 처리하지 않는다.
- Stage 0에서 확인 못 한 범위를 "변경 없음"으로 오판정하지 않는다 — 구분해서 보고한다.
- `raw_v1/`, `게임문서/`, `wiki/`, `프로젝트_위키/`는 레거시였으며 2026-08-17에 삭제됐다(각각
  `raw/`와 중복, `게임가이드/`로 대체, `게임가이드/`로 대체, 미채택 실험). 되살리거나 소스로 쓰지 않는다.
- Notion 쪽 구조(ADR/트래커 DB 중복, "확정 레퍼런스 DB" 미생성 등)는 이 커맨드의 스코프 밖이다.
  `raw/00_컴플라이언스/노션_위치_지도.md` §3에 알려진 채로 남겨두고, 콘텐츠를 이관·병합·삭제하지
  않는다 — 그건 사람이 결정할 별도 작업이다.
